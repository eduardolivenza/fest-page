# FestPage — API (`apps/api`)

Fastify 5, TypeScript (ESM, compiled with `tsc` to `dist/`), Prisma 7. Entry: `src/index.ts` → `buildApp()` in `src/app.ts`.

## Routes

| Prefix | File | Endpoints |
|---|---|---|
| `/api/products` | `routes/products.ts` | `GET /` (`?category=&featured=true&page=&pageSize=` max 50), `GET /:idOrSlug` |
| `/api/contacts` | `routes/contacts.ts` | `POST /` (Turnstile-protected) |
| `/api/orders` | `routes/orders.ts` | `POST /` (customer upsert + order with current product prices) |
| `/api/admin/auth` | `routes/admin/auth.ts` | `POST /login` → `{ token, user }`, `GET /me` |
| `/api/admin/products` | `routes/admin/products.ts` | `GET /`, `GET /:id`, `POST /`, `PUT /:id`, `DELETE /:id` |
| `/api/admin/orders` | `routes/admin/orders.ts` | `GET /`, `PATCH /:id/status` |
| `/api/admin/contacts` | `routes/admin/contacts.ts` | `GET /`, `PATCH /:id/read`, `DELETE /:id` |
| `/health` | `app.ts` | liveness/readiness (does **not** touch the DB) |
| `/docs` | swagger-ui | |

Admin plugins call `app.addHook('preHandler', app.authenticate)` once for the whole file.

## Conventions

- **Validate every body with Zod** (`schema.safeParse`) → `400 { message: 'Invalid data', errors: flatten() }`. Never trust `request.body` directly.
- **Errors are `{ message: string }`.** Status codes in use: 400 invalid input, 401 no/invalid token or bad credentials (same message for unknown user and wrong password), 403 captcha failed, 404 not found, 409 conflict (e.g. product with orders), 201 created, 204 deleted.
- **Prisma errors → HTTP**: catch `Prisma.PrismaClientKnownRequestError`: `P2025` → 404, `P2003` → 409. Import `Prisma` from `../../generated/prisma/client.js` (not `@prisma/client`).
- **Money**: Prisma `Decimal` is converted with `Number()` before returning (see products routes). Orders store `unitPrice` from the product at order time.
- Relative imports end in `.js` (ESM).
- Never return `passwordHash` or tokens other than the login response.

## Auth

Argon2 hashes (`argon2.verify`), JWT signed with `JWT_SECRET` (8h). Payload `{ sub, email }`. The admin app stores the token in `localStorage` (`admin_token`) and sends `Authorization: Bearer`.

## Turnstile (contact form)

`src/lib/turnstile.ts`: enforced only when `TURNSTILE_SECRET_KEY` is set (SealedSecret `fest-descans-api-turnstile`, optional in the chart). Visitor IP from `CF-Connecting-IP` (behind the tunnel `request.ip` is cloudflared). The token field `turnstileToken` is stripped before saving. New public write endpoints should reuse it.

## CORS

Origins from `WEB_URL` and `ADMIN_URL` (chart `cors.*`). A new frontend origin must be added there.

## Prisma 7

- Schema `packages/db/prisma/schema.prisma`; generator `prisma-client` (ESM) **outputs to `apps/api/src/generated/prisma`** (gitignored, regenerated by `postinstall`, compiled with the api).
- DB URL lives in `packages/db/prisma.config.ts` (`process.env.DATABASE_URL`), not in the schema.
- Client: `src/plugins/prisma.ts` with `PrismaPg` adapter (5s connect timeout), decorated as `app.prisma`.
- Commands (from repo root):
  - `pnpm --filter @festpage/db run migrate` → `prisma migrate dev` (does **not** generate or seed in Prisma 7)
  - `pnpm --filter @festpage/db run generate`
  - `pnpm --filter @festpage/db run seed` (seeds admin user + BED/MATTRESS/PILLOW products, no ACCESSORY)
- Production migrations: the api pod's `migrate` initContainer runs `prisma migrate deploy` from `/repo/packages/db`. **Migrations must be backwards compatible** with the previous api version (rolling update: new schema + old pods for a while). Add columns nullable/with default; remove in a later release.
- `ProductCategory` enum exists in both the Prisma schema and `packages/types` — change both.

## Tests

`apps/api/test/*.test.ts`, `pnpm --filter @festpage/api test`. `test/helpers.ts` replaces the Prisma plugin with `vi.fn` fakes, `buildTestApp()` returns `{ app, prisma }`; use `app.inject()`, `adminToken(app)` for admin routes. Every new endpoint gets: happy path, validation 400, auth 401 (admin), and its error mapping (404/409). Real-DB coverage comes from the `Image (api)` PR check (migrations + server against Postgres).
